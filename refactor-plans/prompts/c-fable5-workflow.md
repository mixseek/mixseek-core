# パターンC 実行プロンプト — Fable 5 / ワークフロー（並列ファンアウト）

## 事前準備（人間が実施）

1. モデルを **Fable 5** にする（`/model` で `claude-fable-5`）。
2. ベースから専用ブランチを作成:
   ```bash
   git checkout experiment/refactor-planning-compare
   git checkout -b experiment/refactor-plan-c-fable5-wf
   ```
3. 以下「投入プロンプト」を新規セッションにそのまま貼り付ける。

> B と条件を揃えるため、投入プロンプト本文は B と**出力先・実行条件の1行以外は同一**にしてある。
> どのようなワークフローを設計し、どう起動するかは Fable 5 自身に委ねる（モデルのオーケストレーション能力も検証対象）。

---

## 投入プロンプト（ここから下をコピー）

まず `refactor-plans/prompts/_shared-brief.md` を読み、その指示に従ってください。

**実行条件（パターンC）:**
- あなたは **ワークフロー（Workflow ツール）を使って** 作業します。**どのようなワークフローを設計し、
  どう起動するかはあなた（Fable 5）が決めてください。**（並列ファンアウト等、最良と思う構成でよい）
  - 技術的制約: ワークフローの**スクリプト自体はファイル書き込み不可**。計画本文はエージェントの戻り値として
    受け取り、最終的にあなた（運用セッション）が出力先ディレクトリへ書き出すこと。
- 出力先ディレクトリは `refactor-plans/outputs/c-fable5-wf/` です。このディレクトリ配下にのみ成果物を作成してください。
- 他パターンの出力（`refactor-plans/outputs/a-*`, `b-*`）は参照しないでください。
- コードは変更しないでください（読み取りと計画ドキュメント生成のみ）。

共通ブリーフの「成果物」に従い、`refactor-plans/outputs/c-fable5-wf/README.md`
（計画ドキュメント群を読むためのインデックス＋優先度サマリ表）を必須とし、それ以外のファイル構成は任意です。
完了したら、作成したファイル一覧と概観を報告してください。
